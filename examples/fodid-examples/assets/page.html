🔐 51Did creator context demo

This page runs the 51Degrees client script in your browser, creates a 51Did from what the script reports, verifies that identifier from your browser, and redeems the encrypted creator context result on its own server, which is the only place the licence key lives.

Settings

The deterministic identifier is derived from an email address, so it is the same on every device that address appears on. Clear this box to ask for no deterministic identifier at all.

How the browser reaches the service. Both routes produce the same identifier, and they differ in what the service sees of the visitor's own connection.

Part of this example is missing on this route. The browser is calling this server and this server is calling the service, so the service reads this server's connection and not the browser's, and has no fingerprint of the browser's TLS and HTTP/2 connection, which are called JA4 and H2. The factors that read the visitor's transport are therefore not recorded, and every other factor is checked as normal. The third party route above does have them, because there the browser connects to the service itself.

A real deployment need not lose them either. Whatever terminates the connection in front of the server, which is usually a CDN, works the two fingerprints out and passes them on as the ja4 and h2 request headers, which this example forwards to the service as evidence with no code of its own. Where they arrive this notice does not appear.

🔗 Prove creator context verification. Copy the link below and open it in a different browser (not just a new tab, a genuinely different browser, or another device). The other browser loads this same page with the same 51Did. The signature will still verify and the identifier will unpack, because it is genuine. But the creator context will not validate, because the context binds the identifier to the browser and connection it was created on, and the other browser is neither. A transplanted 51Degrees identifier contains everything needed to tell if it is being used on a different device or network.

Another device? This link names localhost, which on another device means that device, so it will not reach this demo. Another browser on this machine is fine. For a second device, open this page by this machine's network address instead and copy the link again.

⌨️ Or present it from a terminal. Opening the link above in another browser is one way to move the identifier. Running these two commands is another, and it makes the point without a second browser. The first asks the service to verify this 51Did over the terminal's own connection, which returns a sealed result that tells the terminal nothing. The second redeems that result here, where the licence key is, and prints the verdict.

Expect the signature to verify, because the identifier is genuine, and the creator context to come back mismatch, because a terminal is not the browser the identifier was made for.

Transport mismatches will not be identified. This page is calling the service over plain HTTP, so there is no TLS handshake for the service to read, and the transport factor carries its default value at creation and at verification, which always compare as verified. Every other factor is checked as normal. To see the transport factor at work, point the demo at an HTTPS address of the service (the endpoint environment variable in the README) and open the page again.

🎯 Detection demonstrated. This page received a 51Did created in a different browser. The signature verified, so the identifier is genuine, and it unpacked normally. The creator context did not validate, because this browser and connection are not the ones the identifier was created on. A copied, shared or stolen identifier is caught the moment it is presented, with nothing stored server side.
